# Rate plan audit and distribution certification

Decision record: [ADR 0033](adr/0033-rate-plan-audit-and-distribution-certification.md). Everything is read-only. Counts below were run on disposable local PostgreSQL 16 clusters with generated credentials; no persistent database, role, deployment or alias was touched.

## What it is, and is not
- A report on stored rate data, computed with the same evaluator Agent search uses. Admin: **Rates & Inventory > Rate Certification** (needs `supply.rates.read`).
- Not a switch. Nothing is stored or read back: certifying a plan does not change what Agents can search or book.
- Not an editor. It repairs, merges, deletes and publishes nothing. The only POST is the simulator, which writes nothing.

## Routes (`routes.adminRateCertification` in `@bedbanks/contracts`)
| Route | Purpose |
| --- | --- |
| `GET /admin/rate-certification/summary` | Plan, hotel, row-class, finding and remediation counts |
| `GET .../plans` and `.../plans/:ratePlanId` | Plan list (filters: status, finding, live, hotelId, q, paging) and the detail audit with a night-by-night calendar |
| `GET .../hotels` | Hotel distribution readiness |
| `GET .../markup-rules` | Markup rule audit |
| `GET .../remediation` | P0/P1/P2 queue |
| `POST .../simulate` | Read-only price simulator |
| `GET .../report?format=json|markdown` | Exportable report (generated by the API, downloaded by the browser) |

All take `days` (1-365, default 90) and `from`. Invalid input is a 400, another tenant's id is a 404, no permission is a 403.

## Findings
| Code | Severity | Meaning |
| --- | --- | --- |
| `RATE_AMOUNT_ZERO` | FAIL | Zero amount: legacy rows only, new writes are refused ([ADR 0034](adr/0034-daily-rate-amount-must-be-positive.md)); the evaluator refuses the night |
| `RATE_CURRENCY_MISMATCH` | FAIL | Row currency differs from the plan's |
| `RATE_BASIS_UNVERIFIED` | FAIL | Basis is neither NET nor SELL |
| `NET_MARKUP_MISSING` | FAIL | NET night with no ACTIVE markup rule |
| `PLAN_CURRENCY_NOT_ENABLED`, `PLAN_CONTRACT_CURRENCY_MISMATCH` | FAIL | Currency policy (ADR 0029) and contract settlement |
| `OCCUPANCY_EXCEEDS_ROOM` | FAIL | Plan occupancy above the room maximum |
| `PLAN_CONTRACT_NOT_ACTIVE` | FAIL | Live plan, contract EXPIRED or not ACTIVE |
| `NO_PRICED_NIGHTS` | FAIL | Nothing the evaluator can price in the window |
| `DUPLICATE_PLAN_CODE`, `DUPLICATE_LOGICAL_PLAN` | FAIL | Same code across contracts of a hotel; same room, board, contract, occupancy, currency and refundability under another code |
| `RATE_GAPS`, `AVAILABILITY_GAPS`, `NO_SELLABLE_NIGHTS` | WARN | Coverage |
| `RATE_MIXED_BASIS`, `RATE_OUTSIDE_CONTRACT`, `RATE_OTHER_OCCUPANCY` | WARN | Row hygiene |
| `PLAN_CODE_FORMAT`, `CONTRACT_EXPIRING`, `SALES_MARKETS_NOT_ENFORCED` | WARN | Governance and risk |
| `MARKUP_ZERO_PERCENT`, `MARKUP_VERY_HIGH` | WARN | ACTIVE markup rules (0% or above 50%) |
| `PLAN_NOT_LIVE` | INFO | Plan is not ACTIVE: reported, not certified |

Hotel status: **NOT_READY** if there is no live plan, any live plan is FAIL, a readiness gate FAILs or nothing is sellable; **READY_WITH_WARNINGS** if any plan or gate warns; otherwise **CERTIFIED**.

## Applicability: what does not exist in fBeds
These are not audited and never reported as passed.

| Concept in the other specification | fBeds |
| --- | --- |
| Pricing layers and promotions | One contracted rate and one markup rule per night |
| Agent extra markup | Tenant, supplier or hotel markup rule only (ADR 0018) |
| Event supplements | No model |
| SGL / DBL / TPL columns | A plan prices one numeric occupancy |
| Meal Plan Master | `BoardBasis` reference table, already checked by the evaluator |
| Bulk Rate Loader | None; rates are authored by Quick Update and supply routes |
| Whole-AED rounding | Exact minor units; half-up markup in `@bedbanks/pricing` |
| Source-market pricing | Recorded on contracts, not applied by search (WARN) |

Impossible by constraint (no check, by design): duplicate (plan, date, occupancy) rows, overlapping ACTIVE markup rules for one target, malformed active rules (`loadActiveMarkupRules` fails closed).

After an ACTIVE markup rule: hotels 2 CERTIFIED, 1 READY_WITH_WARNINGS, 5 NOT_READY; VALID 31.

**Browser seed** (`seed-rate-certification.ts`, 90 nights): 12 hotels, 13 plans (12 live): 2 PASS, 4 WARN, 6 FAIL; hotels 2 CERTIFIED, 4 READY_WITH_WARNINGS, 6 NOT_READY; rows VALID 848, QUARANTINED 183, DEAD 7, OUTSIDE_CONTRACT 0, BLOCKED_NO_MARKUP 90; remediation 4 P0, 7 P1, 2 P2.

## Verification
- `rate-plan-audit.spec.ts`: 22 unit tests (pure audit, markup audit, simulator).
- `rate-certification.e2e-spec.ts`: 13 tests over HTTP with two tenants: exact counts, 401/403/404/400, filters and paging, remediation order, simulator parity with the Sellability Inspector, read-only proof (no row, timestamp or audit event changes), report, and the strict non-bypass role including a denied markup read.
- `tools/admin-ops-verify/verify-rate-certification.cjs`: 69 checks in Chromium on the production Admin build (counts, filters, detail, simulator, report downloads, failure states, read-only requests, overflow at 1280/768/390 px, axe, viewer and tenant isolation). Run `seed-rate-certification.ts` first.

## Not covered
Production data (no approved clone), supplier connector inventory, booking-time pricing (booking is disabled), and validation of `DailyRate_amount_positive` on a persistent database (an owner step in ADR 0034).
