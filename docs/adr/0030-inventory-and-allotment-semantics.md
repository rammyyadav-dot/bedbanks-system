# ADR 0030: Inventory & Allotment semantics

Status: Accepted (P0.4). Supersedes the "not built" lines for pools, closed to departure, freshness, free sale and on request in the Hotel Operations conformance record.

## Context
Admin Hotel Operations, the Admin calendar, Agent Search, offer presentation, authoritative recheck and sellability each read availability slightly differently: release was judged in UTC days, closed to departure was stored but ignored, a missing row and a zero row were handled in different places, and three rate plans over five rooms could advertise fifteen. Inventory must be one model with one evaluator.

## Decisions
1. **Mode per plan-night.** `DailyAvailability.inventoryMode` is `ALLOTMENT` (counts stock), `FREE_SALE` (sells without counting), `ON_REQUEST` (visible, priced, never instant) or `CLOSED` (never sells). An unknown value is treated as CLOSED. Stop-sell applies to every mode.
2. **Shared pool.** `InventoryPool` (tenant, hotel, supplier, name, status) with per-night `InventoryPoolDay` (capacity, sold, held). A rate plan joins at most one pool (`RatePlan.inventoryPoolId`); a database trigger requires the same tenant, hotel and supplier and an ACTIVE pool; a second trigger refuses a hotel or supplier from another tenant. A pooled ALLOTMENT night draws from the pool day, so three plans over five rooms are five units. The plan row of a pooled plan still carries mode and restrictions; its own counters are not used.
3. **Counter fidelity.** The counter a night was reserved from (`PLAN_ROW`, `POOL_DAY`, `NONE`) is recorded on `InventoryHoldNight` at reservation time; release, confirm and cancel return to that counter even if the plan later leaves a pool. All counter moves are guarded single-statement UPDATEs in `inventory-counters.ts`, locked plan row first, then pool day; CHECK constraints (`sold + held <= capacity`, non-negative) are the backstop.
4. **Missing is unknown.** A missing plan row or pool day is `AVAILABILITY_MISSING`, never zero. Admin never creates stock implicitly except when the operator sets an allotment or capacity.
5. **Hotel-local release.** A plan stops selling a check-in at `releaseTimeLocal` (HH:mm) `releaseDays` hotel-local calendar days before arrival, in `Hotel.timeZone`. Sellable iff `now < deadline` (the deadline instant itself is not sellable). A local time that does not exist (DST gap) resolves to the later instant; one that occurs twice resolves to the earlier. A missing or invalid zone fails closed. Replaces the UTC `leadDays` comparison.
6. **Closed to arrival / departure.** CTA applies to the first night; CTD applies to the `closedToDeparture` flag of the row dated on the **departure** date. A CTD on a night the guest stays through, or on the check-in date, does not block. A missing departure row is not closed.
7. **Freshness.** Rows carry `source`, `sourceUpdatedAt`, `receivedAt`, `freshUntil`. Fresh iff `now < freshUntil`. No expiry is allowed only for non-supplier sources (admin, contract, system); a `SUPPLIER_*` row without `freshUntil` is stale. A stale night fails closed (`INVENTORY_STALE`) in search, recheck, hold and Admin readiness. Admin edits stamp source ADMIN, fresh, no expiry.
8. **One evaluator.** `evaluateContractedStay` takes an evaluation instant and returns stable codes: `AVAILABILITY_MISSING, NO_INVENTORY, POOL_EXHAUSTED, STOP_SELL, INVENTORY_CLOSED, ON_REQUEST_ONLY, INVENTORY_STALE, CLOSED_TO_ARRIVAL, CLOSED_TO_DEPARTURE, MIN_STAY_NOT_MET, MAX_STAY_EXCEEDED, RELEASE_DAYS_NOT_MET` plus an `availabilityStatus` (`available | on_request | unavailable`). Search, recheck, hold verification and Admin calendar/assessment all call it through `buildStaySnapshot`.
9. **Search and recheck.** Search never allocates and never overstates: `limited` when remaining is at or below the requested rooms; ON_REQUEST rates are returned as `availability: on_request, available: false`, are not the headline price while a confirmed rate exists, cannot be selected, and recheck of one is `unavailable`, never an upgrade to confirmed. Recheck keeps the outcomes rechecked / price_changed / unavailable / expired and never substitutes hotel, supplier, room, board or plan.
10. **Admin mutations.** Pool create/rename/members/archive, the release rule, and Quick Update (mode, CTD, pool capacity written once per pool night) are idempotent (key + request hash; same key with a different body is refused), compare-and-set on `updatedAt` or a preview fingerprint, advisory-locked per hotel, tenant-scoped from the session, and audited in the same transaction: `inventory.pool.created, inventory.pool.member_added, inventory.pool.member_removed, inventory.pool.updated, inventory.daily.updated, inventory.bulk.updated, inventory.mode.changed, inventory.release.changed`. Existing permissions (`supply.availability.read/manage`) are reused; no new permission is introduced.
11. **Joining a pool** is refused while the plan has sold or held units on future nights on its own row (double counting); a plan in another pool is never moved silently; a pool with members or committed units cannot be archived.

## Consequences
- Migrations `202610160001_inventory_allotment_foundation` and `202610160002_inventory_pool_tenant_guard` are forward-only. Existing rows default to ALLOTMENT / ADMIN / no expiry, so existing behaviour is unchanged. Rollback notes are in the migration headers.
- Runtime roles (certified in `docs/p04-postmerge-inventory-certification.md`): the API runtime role reads `InventoryPool`, `InventoryPoolDay`, `RatePlan`, `DailyAvailability` and `CancellationPolicy` and **writes none of the pool tables**; `verifyApiRuntimeRole` fails if it can. The hold-expiry role reads `InventoryPoolDay` and updates only its `held` and `updated_at` columns, inside one tenant context at a time. Both rely on forced row-level security; no tenant context means no rows.
- Domain contract: `SearchRateOffer.availability` gains `on_request`.

## Not decided here
Per-plan consumption reporting inside a pool (now ADR 0036); supplier-pushed inventory feeds (live suppliers are out of scope); moving a plan between pools with sold units; nationality, market, promotion, extra-bed, child, tax and currency rules.
